# Задачи — минималистичный список дел

Одностраничное приложение для задач на чистых HTML, CSS и JavaScript. Без фреймворков, сборщиков, npm, CDN и внешних API: всё лежит в репозитории и работает офлайн. Открывается двойным кликом по `index.html`, а на GitHub Pages превращается в устанавливаемое PWA.

Главный принцип — обязательные сценарии должны работать всегда: добавить, отметить, удалить и не потерять данные после перезагрузки. Расширенные возможности (списки, сроки, подзадачи, поиск, drag and drop) не мешают базовому сценарию: при первом открытии виден только заголовок, поле ввода и пустое состояние.

## Быстрый старт

1. Скачайте папку или клонируйте репозиторий.
2. Откройте `index.html` двойным кликом.
3. Напишите задачу и нажмите Enter.

Для проверки логики откройте `tests.html` — тест-раннер самописный и не требует сервера.

> На `file://` приложение работает, но service worker не регистрируется: офлайн-кэш включается только по `http(s)`. В некоторых браузерах (например, Safari) `localStorage` на `file://` может быть ограничен — тогда приложение покажет предупреждение и продолжит работать в памяти.

## Возможности

**Обязательное**

- Добавление по кнопке и по Enter. Пустые строки и одни пробелы не добавляются, пробелы по краям обрезаются, название ограничено 200 символами.
- Отметка выполненных и снятие отметки.
- Удаление задач.
- Сохранение всего состояния в `localStorage` — данные переживают перезагрузку.

**Расширенное**

- Списки: создание, переименование, удаление, цвет, счётчик активных задач. «Входящие» — системный список, его нельзя удалить или переименовать.
- Приоритеты: нет, низкий, средний, высокий. Обозначаются цветом, формой и текстом одновременно.
- Сроки: «Сегодня», «Завтра», «Просрочено на N дн.», даты через `Intl.DateTimeFormat('ru-RU')`.
- Редактирование: двойной клик по названию — быстрая правка (Enter сохраняет, Esc отменяет); кнопка с карандашом — полный диалог со сроком, приоритетом, списком, тегами и подзадачами.
- Подзадачи с прогрессом «2 из 5» и полоской прогресса.
- Поиск по названию и тегам, фильтры (все, активные, выполненные, просроченные, на сегодня), сортировка (вручную, по сроку, по приоритету, по дате добавления).
- Drag and drop задач за точки слева — Pointer Events, работает мышью, пальцем и пером. Доступная альтернатива: кнопки «выше/ниже» и Alt+↑ / Alt+↓.
- Отмена удаления: тост «Задача удалена — Отменить» на 6 секунд; Ctrl+Z отменяет последнее действие.
- Быстрый ввод: срок, приоритет и теги прямо в строке.
- Статистика: выполнено сегодня, за 7 дней, всего, процент выполнения и SVG-кольцо.
- Экспорт и импорт JSON со строгой валидацией и подтверждением замены.
- Темы: светлая, тёмная, системная. Выбор сохраняется, при загрузке нет «мигания» неправильной темы.
- Синхронизация между вкладками через событие `storage`.
- Горячие клавиши и окно подсказки по `?`.
- Анимации: прорисовка галочки, появление и исчезновение задач, компактный canvas-эффект, когда все задачи выполнены. Всё отключается при `prefers-reduced-motion`.
- PWA: manifest, иконки, офлайн-кэш. HTML отдаётся по стратегии network-first, чтобы не застрять на старой версии.

## Быстрый ввод

| Что написать | Что получится |
| --- | --- |
| `сегодня`, `завтра`, `послезавтра` | срок на соответствующий день |
| `25.12` | 25 декабря текущего года; если дата уже прошла — следующего |
| `25.12.2026` | конкретная дата |
| `!1` | низкий приоритет |
| `!2` | средний приоритет |
| `!3` | высокий приоритет |
| `#дом` | тег «дом» (до 8 тегов, без учёта регистра дублей) |

Пример: `Купить молоко завтра !3 #дом` → задача «Купить молоко» со сроком на завтра, высоким приоритетом и тегом «дом».

Подсказка под полем ввода показывает распознанные срок, приоритет и теги ещё до добавления. Если в строке остались только метаданные (например, `завтра !2`), задача не создастся — попросим добавить название.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `N` | фокус на поле новой задачи |
| `/` | фокус на поиск |
| `Ctrl+Z` (или `⌘Z`) | отменить последнее действие |
| `?` | окно подсказки по клавишам |
| `Esc` | закрыть меню / сбросить поиск и фильтры / выйти из правки |
| `Alt+↑`, `Alt+↓` | переместить задачу в ручном порядке |
| `Enter` | сохранить правку названия или подзадачу |
| `Esc` | отменить правку названия |

Горячие клавиши не перехватываются, когда курсор в поле ввода. `Ctrl+Z` внутри текстового поля оставлен браузеру.

## Локальный запуск

Достаточно открыть `index.html`. Если хочется проверить service worker и установку PWA, поднимите любой статический сервер в папке проекта, например:

```bash
python -m http.server 8080
```

Затем откройте `http://localhost:8080/`. На localhost service worker тоже работает.

Тесты: откройте `tests.html` — страница сама запускает набор и показывает зелёные/красные результаты. Подробнее — ниже.

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите файлы в ветку `main` так, чтобы `index.html` лежал в корне.
2. В настройках репозитория: **Settings → Pages → Build and deployment → Deploy from a branch**.
3. Выберите ветку `main` и папку `/ (root)`, сохраните.
4. Через минуту приложение будет доступно по адресу `https://<логин>.github.io/<репозиторий>/`.

Все пути относительные, поэтому проект работает и в подпапке GitHub Pages. Файл `.nojekyll` отключает обработку Jekyll и сохраняет структуру папок. Service worker на Pages работает по HTTPS; после первого визита приложение открывается офлайн.

> Если вы меняете файлы проекта, поднимите версию кэша в `sw.js` (`CACHE_NAME`, например `todo-shell-v1.0.1`). HTML загружается по network-first и подхватится сам, а CSS/JS лежат в cache-first — без новой версии кэша браузер может отдать старые файлы.

## Тесты

`tests.html` — минимальный самописный раннер: `suite`, `test`, несколько assert-функций и отрисовка результатов. Никаких зависимостей и сети.

Сейчас в наборе 61 тест. Покрыто:

- добавление: пустой ввод, пробелы, лимит 200, положение новой задачи, значения по умолчанию;
- отметка выполнения и снятие отметки;
- удаление и отмена, границы ручного порядка, перестановка задач;
- списки: создание, переименование, цвет, запрет на удаление «Входящих», перенос задач при удалении списка;
- подзадачи: добавление, отметка, удаление, пустые значения;
- быстрый ввод: все токены, даты, перенос на следующий год, неверные даты, лимиты тегов и длины;
- фильтры и сортировки, поиск по названию и тегам;
- статистика: сегодня, неделя, процент, просрочка;
- миграция данных версии 1 → 2 и мягкая починка повреждённых данных;
- строгая валидация импорта, отказ от мусора и неизвестных версий, сохранность текущих данных при ошибке;
- импорт с заменой состояния и возврат через Ctrl+Z.

`tests.html` открывается и по `file://`, и на GitHub Pages. В консоли дополнительно печатать ничего не нужно — всё видно на странице.

## Как это устроено в двух словах

Один объект состояния (`{ version, lists, tasks, settings }`) живёт в `state.js`. Любое действие пользователя вызывает функцию-действие, которая проверяет входные данные, меняет состояние и кладёт в стек обратную операцию для Ctrl+Z. После этого состояние сохраняется в `localStorage` и перерисовывается.

Рендер не пересобирает страницу: у каждой задачи есть DOM-узел, а сигнатура из полей подсказывает, что именно изменилось. Поэтому фокус и прокрутка не прыгают, а 1000 задач не перерисовываются целиком. Элементы списка обновляются по id, обработчики навешаны на контейнеры — по одному на список задач и навигацию.

Подробности и схемы — в [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Ограничения

- Данные хранятся только в текущем браузере и на текущем origin. Между устройствами и браузерами ничего не синхронизируется: для этого нужен сервер, а его нет по условию.
- Синхронизация вкладок — «последняя запись побеждает». Конфликтов и слияния изменений нет.
- Лимиты: 5000 задач, 50 списков, 50 подзадач на задачу, 8 тегов, 200 символов в названии, импорт до 2 МБ. Лимиты защищают от переполнения квоты `localStorage`.
- «Входящие» нельзя удалить или переименовать, но в него можно добавлять задачи.
- Перетаскивание и кнопки перемещения доступны в сортировке «Вручную». В других режимах порядок задаёт сортировка.
- Service worker не регистрируется на `file://`; офлайн-кэш и установка PWA требуют `http(s)`.
- Нет аккаунтов, облака, напоминаний, повторяющихся задач и вложений — это сознательно вне рамок задания.
- Для работы нужен современный браузер: поддерживаются `dialog`, Pointer Events, CSS-переменные и `Intl`.

## Ручная проверка

1. Пустое поле и одни пробелы: Enter и кнопка «Добавить» ничего не создают, поле подсвечивается.
2. Ввод с пробелами по краям обрезается; 201-й символ не вводится.
3. Задача добавляется Enter и кнопкой, после F5 остаётся на месте.
4. Отметка ставится и снимается; счётчики в шапке и статистика меняются.
5. Удаление: тост с «Отменить» работает 6 секунд; Ctrl+Z возвращает задачу.
6. `Купить молоко завтра !3 #дом` создаёт задачу с нужными сроком, приоритетом и тегом.
7. Списки создаются, переименовываются, меняют цвет и удаляются; задачи удалённого списка переезжают во «Входящие».
8. Двойной клик по названию: Enter сохраняет, Esc отменяет. Диалог задачи сохраняет срок, приоритет, теги и подзадачи.
9. Поиск, все фильтры и сортировки показывают корректные задачи и живые пустые состояния.
10. Drag and drop мышью и пальцем меняет порядок; Alt+↑/↓ и кнопки делают то же с клавиатуры; после F5 порядок сохраняется.
11. Темы переключаются, выбор сохраняется; при перезагрузке нет вспышки неправильной темы.
12. Экспорт скачивает JSON. Импорт мусора показывает ошибку и не трогает данные. Импорт валидного файла спрашивает подтверждение; после него работает Ctrl+Z.
13. Две вкладки: изменение в одной появляется во второй с уведомлением.
14. Телефон 320px: боковая панель — шторка, зоны нажатия не меньше 44px, нет горизонтального скролла, учтены safe-area.
15. Только клавиатура: Tab и Shift+Tab обходят все действия, фокус видим, `?` открывает подсказку. PWA устанавливается, после перезагрузки без сети приложение открывается.
