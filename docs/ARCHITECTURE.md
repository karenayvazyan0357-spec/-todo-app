# Архитектура

Документ объясняет, как устроено приложение «Задачи», почему выбраны такие решения и где проходят границы ответственности модулей. Его можно читать как сопровождение к коду и как основу для рассказа о проекте на собеседовании.

## 1. Цели и ограничения

- Работать без сборки, npm и внешних зависимостей: открыть `index.html` двойным кликом и получить рабочее приложение.
- Гарантировать четыре обязательных сценария: добавление, отметка, удаление, сохранение после перезагрузки.
- Не усложнять первый экран: расширенные возможности не должны ломать базовый сценарий.
- Быть отзывчивым на 1000+ задач и корректным при недоступном или повреждённом `localStorage`.
- Работать на GitHub Pages как PWA: офлайн, установка, обновление без «застревания» на старой версии.

Отсюда следуют технические рамки: обычные `<script defer>` вместо ES-модулей, один глобальный неймспейс `window.TodoApp`, отсутствие `innerHTML` с пользовательскими данными, все данные — в одном объекте состояния.

## 2. Схема данных

Версия схемы: **2**. Ключ хранилища: **`todo-app:v2`**.

```json
{
  "version": 2,
  "lists": [
    {
      "id": "inbox",
      "name": "Входящие",
      "color": "neutral",
      "createdAt": "2026-02-10T09:00:00.000Z"
    }
  ],
  "tasks": [
    {
      "id": "t_8f3c…",
      "title": "Купить молоко",
      "done": false,
      "createdAt": "2026-02-10T09:12:00.000Z",
      "completedAt": null,
      "due": "2026-02-11",
      "priority": 3,
      "listId": "inbox",
      "tags": ["дом"],
      "subtasks": [
        { "id": "s_1a2b…", "title": "Взять сумку", "done": false }
      ],
      "order": 1
    }
  ],
  "settings": {
    "theme": "system",
    "listId": "inbox",
    "filter": "all",
    "sort": "manual"
  }
}
```

Правила:

- `id` — строки до 64 символов; задачи `t_…`, списки `l_…`, подзадачи `s_…`.
- `due` — локальная дата `YYYY-MM-DD` или `null`. Не `Date`, чтобы не зависеть от часового пояса при сериализации.
- `createdAt` и `completedAt` — ISO-строки UTC. ISO-строки сортируются лексикографически, поэтому не нужно парсить даты при сортировке.
- `priority`: `0` — нет, `1` — низкий, `2` — средний, `3` — высокий. В быстром вводе `!1`, `!2`, `!3` соответствуют этим уровням (в задании `!3` — высокий).
- `order` — число для ручной сортировки. При перестановке значения нормализуются до `1..n` внутри списка.
- `settings.theme`: `light | dark | system`; `filter`: `all | active | done | overdue | today`; `sort`: `manual | due | priority | created`.

**Почему настройки внутри состояния.** Выбранный список, фильтр, сортировка и тема — часть пользовательского контекста, они тоже сохраняются. Поисковый запрос, раскрытые подзадачи и режим правки — эфемерные: живут в `window.TodoApp.view` и не попадают в `localStorage`, чтобы после перезагрузки не открывать приложение в странном состоянии.

**Версионирование и миграция.** `schema.migrate()` понимает версию 1 (данные ранней версии: `text` вместо `title`, `completed` вместо `done`, строковый приоритет) и приводит их к версии 2. Неизвестная версия — не повод падать: данные откладываются в резервный ключ, приложение стартует с пустым списком и предупреждением.

## 3. Поток данных

Однонаправленный поток: **событие → действие → мутация состояния → emit → сохранение + рендер**.

```text
пользователь нажимает «Отметить»
        │
        ▼
делегированный обработчик в app.js            (один слушатель на весь список)
        │
        ▼
store.actions.toggleTask(id)                  (проверка, мутация, inverse для undo)
        │
        ▼
store.emit('task:toggle')
        │
        ├── handleChange → storage.save(state)  (try/catch, квота)
        │
        └── render.update()                     (точечный diff по id)
```

Ключевые свойства:

- Мутации состояния происходят **только** в функциях-действиях `state.js`. Рендер и обработчики не меняют `tasks`/`lists` напрямую.
- Все подписчики вызываются синхронно после мутации. Поэтому порядок «сохранить, потом нарисовать» гарантирован, а при удалении можно сразу передать фокус следующей задаче.
- Ошибка сохранения не отменяет действие: состояние остаётся в памяти, показывается ненавязчивый тост. Пользователь продолжает работать.
- `state:sync` — особый случай: данные пришли из другой вкладки, повторно писать их в `localStorage` не нужно (иначе возможен пинг-понг событий).

## 4. Модули

| Модуль | Ответственность |
| --- | --- |
| `util.js` | даты и `Intl`, обрезка текста, id, DOM-хелперы, `isEditableTarget` |
| `icons.js` | SVG-иконки одного стиля; данные — массивы примитивов, без `innerHTML` |
| `schema.js` | лимиты, дефолтное состояние, миграция, мягкая и строгая валидация |
| `storage.js` | `localStorage` в `try/catch`, проверка доступности, карантин, сохранение темы |
| `selectors.js` | чистые функции: фильтры, поиск, сортировки, счётчики, статистика |
| `state.js` | фабрика стора: действия, `emit`, стек отмены, порядок задач |
| `ui.js` | тосты (пауза на hover/focus, автоудаление) и `aria-live` объявления |
| `parser.js` | чистая функция быстрого ввода: срок, приоритет, теги |
| `render.js` | keyed-diff задач и списков, бейджи, подзадачи, пустые состояния |
| `dialogs.js` | задача, список, статистика, подтверждение, сообщения, подсказка |
| `dnd.js` | перетаскивание на Pointer Events, автоскролл, индикатор вставки |
| `transfer.js` | скачивание JSON, чтение файла, проверка через схему |
| `fx.js` | компактный canvas-эффект завершения списка |
| `pwa.js` | регистрация service worker только на `http(s)` |
| `app.js` | сборка: ссылки на DOM, делегирование, горячие клавиши, темы, синхронизация |

Стрелки зависимостей: `util` → `schema` → `selectors`/`state` → `render`/`dialogs`/`dnd` → `app`. `pwa` и `fx` почти независимы.

## 5. Рендер и производительность

Полная перерисовка страницы не используется. В `render.js` есть две карты «id → DOM-узел»: для навигации и для задач.

1. Для каждой видимой задачи считается **сигнатура**: `done`, `title`, `due`, `priority`, `listId`, теги, `order`, текущая сортировка, раскрытие и содержимое подзадач.
2. Если сигнатура не изменилась, узел не трогаем — фокус, выделение и прокрутка остаются на месте.
3. Если изменилась — обновляем только метаданные/классы/кнопки, заголовок не пересоздаём.
4. Порядок узлов выравнивается `insertBefore`, только если узел стоит не на своём месте.
5. Пропавшие задачи получают класс `is-leaving`, анимацию 200 мс и удаляются. При `prefers-reduced-motion` узел удаляется сразу.
6. Новые задачи получают `task--enter`; для списков больше 200 задач анимация появления отключается, чтобы не устраивать шторм анимаций.

Почему это отзывчиво на 1000 задач: при переключении галочки меняется сигнатура одной задачи, остальные 999 проходят проверку сигнатуры и не касаются DOM. Вставка новой задачи сначала не требует поиска — узел вставляется по индексу. Синтетическая проверка в Node-шиме (не входит в поставку) показывала порядка 0,25 с на первый рендер 1000 задач и десятки миллисекунд на переключение; реальные цифры зависят от устройства, но запас есть.

**Фокус.** После удаления фокус переходит на кнопку удаления соседней задачи или в поле ввода. После отмены удаления — на кнопку удаления восстановленной задачи. При фильтре «Активные» отмеченная задача исчезает — фокус уходит на соседнюю. Нативный `<dialog>` сам ловит фокус и возвращает его на открывшую кнопку; после закрытия диалога задачи дополнительно фокусируется кнопка редактирования.

**Безопасность.** Пользовательский текст всегда попадает в DOM через `textContent` или `document.createTextNode` (внутри `el()`), в атрибуты — через `setAttribute`. `innerHTML` с данными не используется нигде. Иконки строятся через `createElementNS`.

## 6. Хранение и устойчивость

Все обращения к `localStorage` инкапсулированы в `storage.js`.

- **Проверка доступности**: один раз пишем/удаляем пробный ключ. `SecurityError` в Safari на `file://` или приватный режим не роняют приложение.
- **Чтение**: `JSON.parse` в `try/catch`; затем `schema.migrate` и мягкая нормализация `sanitizeSnapshot`. Битые записи отбрасываются поштучно, а не весь файл.
- **Карантин**: если JSON не парсится или версия не поддерживается, исходная строка сохраняется в `todo-app:v2:corrupt-<ISO>`, а не удаляется.
- **Квота**: ошибка `QuotaExceededError` превращается в понятный тост; состояние остаётся в памяти. Приложение не пытается молча потерять данные.
- **Лимиты**: 5000 задач, 50 списков, 50 подзадач, 8 тегов по 24 символа, 200 символов названия, импорт 2 МБ. Лимиты проверяются и на вводе, и при импорте.
- **Тема**: кроме `settings.theme` в состоянии, пишется зеркало `todo-app:theme`. Его читает inline-скрипт в `<head>` до первой отрисовки — так нет вспышки светлой темы в тёмной.

## 7. Отмена действий

Стек хранит не снимки всего состояния, а **обратные операции**:

- добавили задачу — обратная операция удаляет её по id;
- удалили — вставляет обратно по сохранённому индексу;
- изменили поля — возвращает только изменённые ключи;
- переставили — восстанавливает массив `order` по id;
- импортировали — возвращает предыдущий объект состояния целиком.

Глубина стека — 30. Это дешевле, чем копировать 1000 задач на каждое действие, и даёт корректный Ctrl+Z. Тост «Отменить» после удаления не зависит от стека: он вызывает `restoreTask()` с сохранённым объектом задачи и индексом, поэтому не отменит чужое действие, если пользователь успел что-то сделать.

## 8. Быстрый ввод

`parser.js` — чистая функция `parseQuickInput(text, now)`. Она не знает ни о DOM, ни о состоянии, поэтому покрыта тестами отдельно.

- Токены разделяются по пробелам; хвостовая пунктуация (`завтра,`) не мешает.
- Слова `сегодня/завтра/послезавтра` дают смещение от сегодняшней локальной даты.
- `25.12` — текущий год; если дата уже прошла — следующий. `25.12.2026` — конкретный год.
- `!1/!2/!3` — низкий/средний/высокий.
- `#тег` — до 8 тегов, дубли без учёта регистра отбрасываются, решётка в данные не попадает.
- Нераспознанные токены остаются в названии. Некорректная дата (`32.13`) не удаляется из текста.
- Название нормализуется: схлопываются пробелы, обрезаются края, применяется лимит 200.

Если после разбора название пустое, задача не создаётся: приложение просит добавить текст. Подсказка под полем показывает распознанные значения до сохранения.

## 9. Порядок и drag and drop

`order` — числовой ключ ручной сортировки. Операции:

- **Добавление**: новая задача получает `min(order) - 1` в своём списке — появляется сверху, сразу видна после добавления.
- **Кнопки/Alt+↑↓**: массив задач списка, отсортированный по `order`, меняет два элемента местами, затем нормализуется до `1..n`.
- **Drag and drop**: перетаскиваемая задача вставляется до или после ближайшей видимой цели; порядок пересчитывается по всему списку, поэтому работает и при активном фильтре.

Перетаскивание устроено на Pointer Events:

1. `pointerdown` на ручке-«точках» (не на всей карточке — чтобы не мешать выделению текста и прокрутке), `touch-action: none`.
2. Порог 5 px — клик по ручке не считается перетаскиванием.
3. При захвате рисуется индикатор вставки (`is-drop-before/after`) на целевой карточке; автоскролл у краёв экрана.
4. `pointerup` вызывает действие, `pointercancel`/Esc отменяют.
5. Клавиатурная альтернатива: кнопки «выше/ниже», стрелки на ручке, Alt+↑/↓ на карточке.

Перестановка доступна только в сортировке «Вручную»: в остальных режимах порядок задаёт сортировка, и ручка скрыта. Это осознанное ограничение, чтобы поведение было предсказуемым.

## 10. Экспорт и импорт

Экспорт формирует объект с `app`, `version`, `exportedAt`, `lists`, `tasks`, `settings` и скачивает его как `tasks-YYYY-MM-DD.json` через `Blob` + `URL.createObjectURL`.

Импорт:

1. Проверка размера файла (2 МБ) до чтения.
2. `FileReader.readAsText`; ошибка чтения — понятное сообщение.
3. `JSON.parse`; ошибка — сообщение без изменения данных.
4. `schema.migrate` — поддержка версии 1.
5. `schema.validateSnapshot` — строгая проверка: версия, массивы и лимиты, типы полей, уникальные id, существование списка у задачи, диапазон приоритета, формат дат, размер тегов и подзадач.
6. Любая ошибка → диалог со списком проблем; текущее состояние даже не копируется.
7. Успех → подтверждение «Заменить данные?» с количеством задач и списков.
8. Замена через `importState`, которая кладёт предыдущее состояние в стек отмены. Ctrl+Z возвращает всё назад.

Строгая проверка намеренно не «чинит» чужой файл молча: пользователь должен видеть, что именно не так. Мягкая нормализация применяется только к своему хранилищу, где важно спасти максимум.

## 11. Темы

В CSS две палитры: `[data-theme="light"]` и `[data-theme="dark"]` (светлая — в `:root`). Значение `system` разрешается в JS через `matchMedia` и тоже превращается в конкретную тему — CSS не содержит третьего набора правил.

Порядок загрузки:

1. Inline-скрипт в `<head>` читает зеркало `todo-app:theme` и ставит `data-theme` до применения стилей.
2. После загрузки приложение берёт `settings.theme`, при необходимости поправляет тему и записывает зеркало.
3. При смене системной темы и режиме `system` тема пересчитывается без перезагрузки.
4. `meta[name="theme-color"]` обновляется под текущий фон, чтобы адресная строка мобильного браузера совпадала.

Контраст: текст и фоны подобраны под WCAG AA для обычного текста; для границ полей и чекбоксов введён отдельный токен `--control-border` с контрастом не ниже 3:1. Приоритеты дублируются цветом, формой и текстом.

## 12. Синхронизация вкладок

`storage`-событие приходит в другие вкладки того же origin. Обработчик:

1. Игнорирует не наш ключ и удаление ключа.
2. Перечитывает и валидирует сохранение через `storage.load`.
3. Если данные битые — показывает предупреждение и **не** затирает текущее состояние.
4. Иначе `store.replace(state, 'state:sync')`: состояние меняется, undo-стек очищается, рендер и тема обновляются.
5. Для `state:sync` сохранение пропускается — иначе вкладки могли бы бесконечно пересылать одно и то же.

Модель — last-write-wins. Для локального приложения без сервера этого достаточно; настоящее слияние потребовало бы версий и конфликтов.

## 13. PWA и офлайн

- `manifest.webmanifest` описывает имя, цвета, `standalone`, SVG-иконку, PNG 192/512 и maskable-иконку.
- `sw.js` кэширует оболочку при установке (`cache.addAll`), версия кэша — в имени `todo-shell-v1.0.0`.
- **HTML — network-first**: при каждом переходе сначала сеть, при офлайне — кэш. Это защищает от застревания на старой версии.
- **Статика — cache-first**: CSS/JS/иконки неизменяемы в пределах версии кэша; при промахе запрос идёт в сеть и кэшируется.
- `skipWaiting` + `clients.claim` активируют новую версию; `pwa.js` слушает `controllerchange` и предлагает «Обновить», не перезагружая страницу без согласия.
- Регистрация обёрнута в проверку `serviceWorker` и протокола: на `file://` ничего не происходит.
- Офлайн-тест: открыть по HTTPS/localhost, включить офлайн в DevTools, перезагрузить — приложение поднимается из кэша.

## 14. Доступность и движение

- Семантика: `main`, `aside`, `nav`, `ul/li`, `form`, `dialog`, `button`; `lang="ru"`.
- Все действия доступны с клавиатуры; видимый `:focus-visible`; пропуск к содержимому.
- Кастомные чекбоксы — `button role="checkbox"` с `aria-checked` и понятными `aria-label`.
- Раскрытие подзадач — `aria-expanded` и `aria-controls`; активный список — `aria-current`.
- Уведомления: `aria-live="polite"` для голосовых объявлений, тосты — визуальное дублирование.
- Диалоги — нативный `<dialog>`: ловушка фокуса, Esc, возврат фокуса.
- Мобильное меню блокирует фон через `inert`, закрывается кликом по затемнению и Esc.
- `prefers-reduced-motion`: отключаются анимации, переходы и canvas-эффект.
- `prefers-color-scheme`: используется как значение по умолчанию для темы «Системная».

## 15. Ключевые решения и компромиссы

| Решение | Почему | Компромисс |
| --- | --- | --- |
| Без ES-модулей, один неймспейс | работает по `file://`, нет сборки | ручной порядок подключения `defer` |
| Один объект состояния + действия | предсказуемость, тестируемость, единая точка сохранения | все изменения проходят через `state.js` |
| Точечный keyed-diff | фокус, прокрутка, 1000 задач | сигнатуры нужно поддерживать при добавлении полей |
| `order` числами | простая ручная сортировка и DnD | нормализация при перестановке |
| Мягкое чтение своего хранилища и строгое чтение импорта | спасти максимум своего и не пускать мусор | два режима валидации |
| Обратные операции для undo | дешевле снимков состояния | нужно аккуратно писать inverse для каждого действия |
| `last-write-wins` для вкладок | без сервера это честно и предсказуемо | нет слияния одновременных правок |
| DnD только в ручном порядке | не спорит с сортировкой | в других режимах ручка скрыта |
| Network-first для HTML | пользователь не застревает на старой версии | первый офлайн-заход после обновления требует кэша |
| Тема через `data-theme` + зеркало | нет вспышки неправильной темы | два места хранения темы |
